## 已修复的问题

| 问题与复现依据 | 修复方案 | 文件 |
|---|---|---|
| 复制旧报价后换门店或改 `fetchedAt`，仍会返回旧价方案 | 报价状态绑定门店、就餐方式、快照时间及官方数据 SHA-256 指纹；变化或缺失时清空缓存并重置新轮次预算 | `src/mcd_compromise/quote_context.py`、`quote_state.py`、`plan_cli.py` |
| 报价没有有效时间校验，接受方案后的重报仅写在提示中 | 300 秒缓存期限；异常、缺失或超前超过 30 秒的报价失效；接受方案后首次推进使用 `--force-requote` | 同上 |
| 历史样本和实时规划没有明确区分 | 新增 `--replay`，输出回放标识及历史价格说明；实时输入要求 `fetchedAt`，两阶段宿主须保留完整 `quotes.context` | `plan_cli.py`、`make_examples.py`、输出契约及 README |
| 非空商品清单 + 零价格仍被登记为有效 | 只接受正整数分，拒绝零、负数、布尔值、非整数及格式错误值；恢复后的零价也不能通过 `Quote.ok` | `models.py`、`quote_state.py` |
| 两个真实脚本各自维护报价解析，容易分叉 | `live_e2e.quote_dict` 复用引擎解析规则；两个脚本回写完整报价上下文；新时间使用 `+08:00` | `scripts/live_e2e.py`、`scripts/live_fast.py` |
| 安装说明漏掉引擎源码目录 | 明确 `SKILL.md`、`references/`、`scripts/`、`src/` 应位于同一 Skill 根目录 | `workbuddy.md`、`README.md` |
| 快速脚本只能通过简写参数构造需求，不能完整保留任意约束和版本 | 新增 `live_fast.py --request meal-request.json`；读取完整需求，拒绝与简写条件混用，保留锁定、优先级、用户原话和版本；无套餐时仍允许单品候选继续规划 | `scripts/live_fast.py`、`SKILL.md` |
| 归档只脱敏部分文件，结果文件内嵌的券引用遗漏；同一替代值可能合并不同候选键 | 成功运行后统一脱敏输出目录全部 JSON 中的券字段及内嵌候选键，为不同值保留不同稳定别名，并同步报价字典键 | `scripts/live_fast.py` |
| `workbuddy.md` 有错别字，开发摘要与完整会话的区别不清 | 修正项目名、完善开发背景说明，标明完整会话待导出 | `workbuddy.md` |
